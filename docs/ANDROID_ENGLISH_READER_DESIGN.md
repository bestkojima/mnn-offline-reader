# Android 跨应用英语查词与朗读方案

下一阶段目标已记录：[英语长文连续朗读](LONG_TEXT_READING_PLAN.md)。采用按句切分、播放期间预合成及受限 PCM 缓冲；当前 Release 尚未实现该流水线。

记录日期：2026-10-11。状态：用户已确认第一版采用居中卡片、Supertonic 3 MNN int8 和本地数据库；已实现首个安卓版本并完成本机构建与合成验证，真机验收待进行。

## 已确认的选择

- 语音模型：**Supertonic 3 MNN int8 + Kokoro-82M v1.0 中文引擎**。目标为安卓本地朗读，覆盖 v3 的 31 种语言；默认检测语言并允许手动指定，英语单词与句子为主要场景，支持选择预设音色。第一版使用 Android 原生 View，Java → JNI → C++/MNN 调用，不在手机中嵌入 Python CLI。
- 数据库：**本地 SQLite 词库 + 精选中英例句**。英语词条、音标、词性、中文释义、词形变化及精选例句离线可查；核心查词离线；首次下载语音包需要网络，下载后发音离线。
- 音频：按需由本地模型合成，不预存所有词条和例句的音频。仅缓存近期播放内容，设置容量上限。
- 云端：可选补充本地缺失词条、更多例句与整句翻译；当前不指定服务商，也不把云端作为核心使用前提。
- 用户数据：生词本、查词历史和用户设置保存在独立本地数据库，词库升级时保留。账号同步暂未选定。

## 模型资产与容量

社区模型包采用 `yunfengwang/supertonic-tts-mnn` 的 **v3/int8** 四个模型，加 v3 的 `tts.json`、`unicode_indexer.json` 和 voice-style JSON。不要混用不同版本配置或同时打包多种精度。固定发布 revision 与文件校验值，保留资产许可证。

按此前文件列表汇总，int8 必要资产合计 **113,368,395 字节，约 113.4 MB / 108.1 MiB**（含十个预设音色）。这是文件占用，不是运行内存，也不是最终 APK 大小。[模型文件列表](https://huggingface.co/api/models/yunfengwang/supertonic-tts-mnn/tree/main/v3?recursive=true&limit=1000)

词库和精选例句含索引暂按 **50–150 MB** 预算；应用、原生库、模型、词库及适量缓存的安装后总占用可先按 **200–400 MB** 规划。这是工程估算，导入数据库和构建后重新测量；下载大小、解压占用与峰值内存分别记录。当前没有测量 int8 在目标安卓设备上的音质、延迟和内存。

## 数据组织

词库建议从 ECDICT 等可用数据源清洗、筛选后导入；ECDICT 自身的例句字段尚不提供所需内容，因此例句另选来源，保留出处、许可和版本信息。英/美音标需按来源分别标记；来源只提供一种时只展示已知项，不生成另一种冒充词典数据。

| 数据 | 建议表与主要字段 | 读写方式 |
| --- | --- | --- |
| 词条 | `entries`：id、headword、normalized_key、phonetic_uk/phonetic_us（可空）、source_id | 随词库发布，以查询为主 |
| 释义 | `senses`：entry_id、词性、中文释义、可选英文释义、顺序 | 支持多词性与多个义项 |
| 词形 | `forms`：normalized_form、entry_id、类型 | 用索引将过去式/复数等关联回词条 |
| 精选例句 | `examples`：entry_id、可选 sense_id、英文、中文、source_id、顺序 | 高频词优先选 2–3 条；覆盖范围待导入时确定 |
| 数据来源 | `sources`：名称、版本、许可、来源地址 | 随内容更新，用于来源追溯 |
| 用户学习记录 | 独立 `user.db`：bookmarks、history、settings | 用户操作时写入，更新词库不覆盖 |
| 可选云端缓存 | 独立缓存：查询键、结构化结果、来源、获取时间、过期时间 | 按需写入，避免改变发布词库 |

第一版对 normalized_key 与 normalized_form 建索引，优先精确匹配和词形还原；只有明确需要全文搜索时再增加全文索引，控制数据库体积。

本地与云端在卡片层统一为同一份 `LookupResult`（词条、音标、释义、例句、来源），但查询过程不同：本地直接访问 SQLite；云端经网络 API，存在延迟、失败和鉴权。先展示本地结果，用户请求补充后再访问云端，结果可缓存；不静默上传屏幕全文。

## 卡片与跨应用入口

推荐起点：长按选中文字 → 系统选区菜单中的“发音”（可能在“更多”里）→ 查词朗读卡片 → 关闭返回原应用。菜单通过 `ACTION_PROCESS_TEXT` 接入；分享文本也进入同一张卡片。来源应用控制是否提供选区菜单，不能保证所有界面都能长按取词。

单词卡片显示：单词、音标、词性与中文释义、单词播放/停止、精选中英例句及其播放按钮、音色、语速、语言检测结果/手动选择、加入生词本、关闭。预览暂以 F1 和 1.0× 展示，不视为已确认默认设置；音色选择不等同于英式/美式口音选择。

整句输入采用句子朗读卡片，显示原文与播放操作；离线词库不负责整句翻译。本地没有词条时显示“本地未收录”，仍可发音，并提供可选联网补充入口。

此前比较了两种布局：

1. **居中卡片**：对话框 Activity，突出单词、发音和简短释义；点击外部、关闭按钮或系统返回结束 Activity。
2. **底部卡片**：相同内容放在底部面板，更适合展示例句和后续详情；仍可用 Activity 呈现，不因布局在底部就必须申请悬浮窗权限。

用户已确认第一版使用**居中卡片**。此前聊天中的交互预览只演示状态；新安卓实现已接入真实 MNN 合成和本地持久化生词本。第一版不加入悬浮取字、OCR 或云端查询。

不可选文字另设可选悬浮入口：无障碍取字或授权截图/OCR → 用户确认文字 → 同一卡片。截图路线、OCR 引擎与覆盖范围在真机调研后确定，不把悬浮窗权限当作读取其他应用文字的能力。

## 实施前验证

1. 固定 v3/int8 资产，验证英语短词、例句、数字和专有名词；与 fp16 参照比较音质。
2. 核对现有 Supertonic 实现的 v3 文本预处理、语言标记、音色维度、模型输入输出与采样率。
3. 安卓 arm64 真机验证合成与播放，记录冷启动/热启动延迟、峰值内存和安装占用。
4. 导入词库与例句后核对来源、音标、词形映射、查询速度和实际容量。
5. 验证选字/分享入口、卡片关闭返回、连续点击的播放替换行为。复用模型并使用串行合成队列，分别处理停止播放与取消合成。

背景与证据：[模型与容量调研](SUPERTONIC3_ANDROID_RESEARCH.md)、[安卓入口与翻译软件调研](ANDROID_TRANSLATION_APP_UX_RESEARCH.md)。

## 第一版实现记录

代码与构建说明：[MnnEnglishReader](../README.md)。本版本使用独立 Application、`PROCESS_TEXT`/`SEND` Activity、原生居中卡片、SQLite 只读词库与独立 `user.db`。主应用使用 ML Kit 随包语言识别及其传递依赖；Supertonic 和 Kokoro 均使用 MNN；当前下载版保留模型下载所需网络权限。

实际资源：模型及十个音色共 113,368,395 字节；SQLite 词库 **9,023,488 字节**，包含 **49,664 词条、52,040 词形关联、24 条中英例句（覆盖 12 个词）**。加入中文前的多语言安装包约 **130 MB**；首次使用还需复制模型和词库，合计资源副本约 122.4 MB，再加应用解压与原生库占用。最终手机安装空间和运行内存仍须测量，不能将 APK 大小作为安装后空间。

资源固定 revision、commit 和 SHA-256，准备脚本校验后生成资产；大模型、数据库和构建产物不提交 Git。许可证和数据来源随 APK 提供，应用内可查看。

已验证：数据库生成与原子替换保护；十三项 Java 文本及语言处理测试；arm64 APK 与测试 APK 构建；安卓 lint；本机 MNN v3/int8 的单词 F1 与整句 M5 合成，以及合成中途取消与恢复。生成 WAV 的采样率为 **44,100 Hz**，PCM16 单声道且能量非零。APK 签名及 16 KB 页面对齐已检查。

未验证：真实安卓 JNI 执行、各来源应用的菜单、卡片触摸/旋转/大字体、来电与耳机打断、冷启动/热启动延迟、峰值内存和主观音质。本次环境未连接安卓设备；已提供设备端集成测试与人工验收清单。

## 多语言与编译补充（2026-10-11）

用户确认在合成之前检测输入语言，按 v3 约定生成 `<en>…</en>`、`<ja>…</ja>` 等标记。它是模型的文本语言条件，不是 LLM 对话模板。支持 31 种语言，不含中文；`na` 不作为可靠中文支持。[官方语言清单](https://huggingface.co/Supertone/supertonic-3#supported-languages)。

采用随包的 `com.google.mlkit:language-id:17.0.6`，第一次也可本地识别，无需 Play Services 下载模型。按整段原文检测；置信度低或候选接近时提示手动选择，卡片始终提供 31 种语言选择。日语/韩语支持无空格文本分段；英语词库与生词本结构保持原方案，其他语言只朗读。英文例句强制英语标记，缓存按标记后的文本隔离语言。检测与播放请求均处理界面关闭及新输入导致的过期结果。[ML Kit Android 文档](https://developers.google.com/ml-kit/language/identification/android)。

构建选择为本仓库源码编译，非下载预编译 MNN 库。Android native 实际编译命令已核对为 `-O3 -DNDEBUG`，启用低内存和 ARM82，MNN 静态链接进 JNI 的 `libenglish_reader.so`；Java 仍可构建 debug 版本。编译开关、是否执行真机和性能测量应分开记录。

多语言版验证记录：13 项 Java 单元测试、2 项数据库脚本测试和 lint 通过，英/西/日/韩/阿拉伯语主机 MNN int8 实际合成输出非零 PCM16 音频；APK 实测 130,080,111 字节。语言识别 SDK 及其传递依赖总共增加约 5.4 MB。APK 中的三个 native 库（MNN JNI、NDK libc++、ML Kit language ID）均有 16 KB LOAD 对齐；MNN JNI 从源码构建，ML Kit language ID 库为供应商预编译库。设备端语言检测与播放测试尚未执行，不把主机的五语言合成当作全部语言的音质验收。

## 中文 Kokoro 接入记录（2026-10-11）

用户确认先接入 Kokoro，并将候选模型记录在[中文 TTS 候选文档](CHINESE_TTS_MODEL_CANDIDATES.md)。本轮采用已有 MNN 输入接口的 v1.0 固定转换权重，两套中文男/女音色，配套中文与英文音素词典；v1.1-zh 保留为后续兼容性与质量候选。Kokoro 资源合计 109,906,786 字节，不打包所有音色或第二套 ONNX Runtime。

语言检测/手动选择得到 `zh` 后路由 Kokoro，其他已支持语言路由 Supertonic。中文前处理为词典最长匹配、词内三声变调及常见数值日期展开，不添加 `<zh>` 标签；未知字/英文词提示用户，不静默省略。英语释义、音标、例句与独立用户库保持原方案。中文使用 24 kHz 播放，Supertonic 使用其资产的 44.1 kHz；音色设置、缓存和采样率按引擎分开，串行切换时释放前一个模型。

19 项 Java、4 项 Python 测试及 lint 通过；真实 Java 前处理 → MNN 的中文男女声、多音词、数字日期及中英混排主机合成完成，取消与恢复通过。原模型内置版 APK 约 234.4 MB，两套引擎和词库使用后的资源副本合计约 232.3 MB；签名及 16 KB 对齐通过，未连接设备，手机性能与主观发音质量仍待验收。


## 2026-10-12：TTS 资源改为 ModelScope 按需下载

用户明确调整：App 不内置 TTS 模型。英语 SQLite 词库与轻量语言检测继续随包，所有 TTS 权重、音色和中文音素词典从 ModelScope 固定 commit 下载。首页与卡片均有“下载语音”入口；中文约 110 MB，其他 31 种语言约 113 MB，可以单独下载。

实现使用独立下载队列，支持 HTTP Range、持久 `.part`、暂停/进程重启恢复、SHA-256 校验和同目录原子重命名。离开下载页暂停；无后台持续下载承诺。未下载提示先下载，下载后离线使用；资源请求不携带选区文字。APK 构建拒绝模型二进制和临时文件。资源仅在内部存储保留一份，不再从 APK 复制一套完整语音模型。

资源已分别发布至 [Supertonic 仓库](https://modelscope.cn/models/dr3334/Supertonic-3-INT8-MNN) 与 [Kokoro 仓库](https://modelscope.cn/models/dr3334/Kokoro-82M-v1.0-MNN)，上游许可和来源保留；完整 commit 和逐文件远端核对在 App 的 `data/modelscope-release.json`。下载实现及最新验证见 [App README](../README.md)。

下载版验证：APK 18,241,712 字节（约 18.2 MB），包内无 TTS 权重、音色或音素词典；29 项 Java、4 项 Python 测试、lint、签名及 16 KB 对齐通过。开发机以 App 实际下载器获取全部 26 个固定资源文件，并完成真实中断/新下载器恢复与逐文件校验；安卓真机测试仍待执行。
